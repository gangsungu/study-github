> 커밋은 변경분이 아니라 **스냅샷**이고, 스냅샷끼리는 페어런트 참조로 이어진 **DAG**입니다. `rebase`가 커밋을 "옮기는" 게 아니라 **새로 만드는** 이유가 여기서 나옵니다.

## 폴더 구조 규칙

새 주제는 **폴더 하나 추가**로 끝납니다.

```
NN-주제이름/
├── 주제이름.md      ← 정리 본문 (주제가 넓으면 여러 문서로 나눈다)
└── examples/       ← 직접 따라 해보는 실습
    ├── 실습-안내.md   ← 실습 목록·실행 방법
    └── exNN-이름.sh   ← 임시 저장소를 만들어 명령을 재현하는 스크립트
```

- **번호는 재사용하지도, 다시 매기지도 않는다.** 중간에 배운 주제가 생겨도 맨 뒤에 새 번호로 붙이고, 읽는 순서는 위 목차에서만 조정한다. 그래야 폴더 경로와 링크가 영원히 안 깨진다.
- **`README.md`라는 이름은 레포 루트에만 쓴다.** 파일 이름만 보고 무슨 문서인지 알 수 있어야 한다.
- **주제가 넓으면 문서를 나눈다.** 폴더 안에 목차 문서를 따로 만들지 말고 **루트 목차에 하위 표로 나열하고**, 문서끼리는 각 문서 끝의 `### 관련 문서`로 연결한다.
- **파일명에 공백을 쓰지 않는다.** 마크다운 링크가 `%20`으로 지저분해지고 터미널에서 매번 따옴표를 씌워야 한다.
- 실습 파일 이름은 **정리 문서의 섹션 순서와 맞춘다.**

### Git 때문에 다른 레포와 다른 부분

- **실습은 이 레포 안에서 하지 않는다.** `rebase`·`reset`·`reflog` 실습을 레포 안에서 하면 공부 기록 자체가 망가진다. 실습 스크립트는 항상 **임시 폴더에 새 저장소를 만들어서** 그 안에서 명령을 실행한다.
- **`.git/` 내부를 들여다보는 명령은 출력까지 문서에 붙인다.** 해시값은 환경마다 달라지므로 값 자체보다 **구조**(어떤 객체가 무엇을 가리키는지)를 설명한다.

## 실습 실행

Git Bash(Windows) 또는 일반 터미널에서 **레포 루트에서** 실행하세요.

```bash
bash 01-Git-내부구조-파헤치기/examples/ex01-이름.sh
```

객체를 직접 확인할 때 자주 쓰는 명령입니다.

```bash
git cat-file -t <해시>   # 객체 타입 (blob / tree / commit / tag)
git cat-file -p <해시>   # 객체 내용
git log --oneline --graph --all   # 커밋 DAG 확인
git reflog               # HEAD가 움직인 기록
```

> Windows 터미널에서 한글이 깨지면 `chcp 65001` 을 먼저 실행하고, 한글 파일명이 `\353\202\264...`처럼 보이면 `git config --global core.quotepath false` 를 설정하세요.
