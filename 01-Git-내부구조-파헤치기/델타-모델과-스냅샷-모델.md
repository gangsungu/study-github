## 델타 모델과 스냅샷 모델

### 델타 모델
+ 현재 버전 전체를 저장하지 않고 이전 버전과 비교해서 변경된 부분만 저장하는 방식
    - CVS, Subversion(SVN) 같은 초기 버전 관리 시스템이 이 방식을 사용
+ 특징
    - 장점
        + 변경된 내용만 저장하기 때문에 저장 공간을 효율적으로 사용할 수 있다
    - 단점
        + 버전이 많아질수록 특정 버전을 재현하기 위해 계산해야 하는 변경사항이 늘어난다
            - 첫 버전을 통째로 두고 이후 변경분을 쌓는 방식(정방향 델타)이라면, 특정 버전을 체크아웃하려면 첫번째 버전부터 목표 버전까지 변경사항을 차례로 누적해야 한다
            - 네번째 버전을 재현하려면 첫번째, 두번째, 세번째를 차례로 적용
            - 차례대로 적용하지 않으면 누락한 버전의 변경사항이 적용되지 않는다
        + 중간의 델타 하나가 손상되면 그 이후 버전을 전부 재현할 수 없다
+ 모든 델타 시스템이 첫 버전부터 계산하는 것은 아니다
    - RCS처럼 **최신 버전을 통째로** 저장하고 과거 버전을 역방향 델타로 저장하면 최신 버전 체크아웃은 빠르지만 오래된 버전일수록 느려진다
    - SVN은 skip-delta로 거쳐야 하는 델타 수를 줄인다
    - 어떤 방식이든 "버전을 재현하려면 델타를 이어 붙여 계산해야 한다"는 한계는 같다

### 스냅샷 모델
+ 스냅샷 모델은 특정 시점의 전체 저장소 상태를 저장한다
    - 델타 모델과 달리 목표 버전으로 바로 이동할 수 있다
+ 특징
    - 변경된 파일은 새 객체로 저장하고, 변경되지 않은 파일은 이미 저장된 객체를 참조만 한다
        + 여기서 말하는 "링크"는 파일 시스템의 링크가 아니라 **객체의 해시값**을 적어두는 것
        + 그래서 매 커밋이 전체 상태를 가지면서도 바뀌지 않은 파일 때문에 용량이 늘지 않는다
    - 체크아웃시 모든 버전을 순회해 적용할 필요가 없어 속도가 빠름
    - Git은 데이터를 저장하기 위해 주모델로 스냅샷 모델을 사용
+ 커밋은 변경분이 아니라 스냅샷이다
    - `git show`, `git diff`가 보여주는 변경사항은 저장된 값이 아니라 **두 스냅샷을 비교해서 그때그때 계산한 결과**
    - 그래서 같은 변경을 다른 커밋 위에 다시 적용하는 `rebase`·`cherry-pick`은 변경분을 "옮기는" 것이 아니라 **새 스냅샷(새 커밋)을 만드는** 작업이다
+ 스냅샷 모델을 사용하면 데이터를 저장하기 위해 많은 저장공간을 사용하지 않을까?
    - 링크 사용, 객체 압축
    - 객체 압축으로도 부족하면 Pack 파일로 압축

### Pack 파일
+ 처음 생성된 객체는 zlib으로 압축된 파일 하나로 저장된다. 이 상태를 **loose object**라고 한다
+ loose object가 많아지면 Git은 여러 객체를 하나의 Pack 파일로 묶는다
    - `git gc`를 실행하거나, loose object가 일정 개수(기본 약 6700개, `gc.auto`)를 넘어 자동 gc가 돌 때
    - `push`·`fetch`·`clone`으로 원격과 객체를 주고받을 때도 Pack 형식으로 전송한다
    - `.git/objects/pack/` 안에 객체 데이터인 `.pack`과 위치를 찾는 색인인 `.idx`가 함께 생긴다
+ Pack 파일 안에서는 **델타 압축**을 사용한다
    - 내용이 비슷한 객체끼리 하나는 통째로, 나머지는 차이만 저장한다
    - 델타 모델과 달리 "직전 버전과의 차이"로 고정되지 않고, 크기·파일명 등이 비슷한 객체를 골라 짝을 짓는다
    - 최근 버전을 자주 꺼내므로 보통 **최신 버전을 통째로** 두고 과거 버전을 델타로 저장한다
+ 정리하면 Git은 **논리적으로는 스냅샷 모델**, **물리적 저장에서는 델타 압축을 함께** 쓴다
    - 사용자가 다루는 단위(커밋, 트리, BLOB)는 언제나 완전한 스냅샷이고, 델타는 저장 공간을 아끼기 위한 내부 최적화일 뿐이다

```bash
git count-objects -v              # count: loose object 수, in-pack: Pack에 들어간 객체 수
git gc                            # loose object를 Pack 파일로 묶는다
git verify-pack -v .git/objects/pack/pack-*.idx   # Pack 안의 객체 목록과 델타 여부
```

```
# git gc 전              # git gc 후
count: 9                 count: 0
in-pack: 0               in-pack: 9
packs: 0                 packs: 1
```
