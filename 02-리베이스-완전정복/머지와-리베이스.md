## 머지와 리베이스

두 명령 모두 **다른 브랜치의 변경을 내 브랜치에 합치는** 데 쓰지만, 히스토리를 남기는 방식이 다르다

### 머지
+ fast-forward 머지
    - 내 브랜치가 상대 브랜치의 조상이라 갈라진 적이 없으면, 새 커밋 없이 **브랜치 포인터만 앞으로 옮긴다**
    - 병합 흔적을 남기고 싶으면 `git merge --no-ff`로 병합 커밋을 강제로 만든다
+ 3-way 머지
    - 두 브랜치가 갈라졌으면 **공통 조상, 내 브랜치 끝, 상대 브랜치 끝** 세 스냅샷을 비교해 합친다
    - 결과로 부모가 2개인 **병합 커밋**이 하나 생긴다
    - 기존 커밋은 하나도 바뀌지 않는다. 해시도 그대로
    - 충돌은 **한 번에 모아서** 해결한다

```
git switch main && git merge feature

      D ── E   ← feature
     /      \
A ── B ── C ── M   ← main      M: 부모가 C, E 두 개인 병합 커밋
```

### 리베이스
+ 내 브랜치의 커밋을 상대 브랜치 끝 위에 **새로 만들어** 일렬로 쌓는다
    - 병합 커밋이 없고 히스토리가 **한 줄**이 된다
    - 내 브랜치의 커밋 해시가 **전부 바뀐다**
    - 커밋을 하나씩 적용하므로 충돌도 **커밋마다** 해결해야 할 수 있다
+ 리베이스 후 `main`에서 머지하면 갈라진 곳이 없어 fast-forward로 끝난다

```
git switch feature && git rebase main
git switch main && git merge feature     # fast-forward

A ── B ── C ── D' ── E'   ← main, feature
```

### 비교

| | 머지 | 리베이스 |
|---|---|---|
| 히스토리 모양 | 갈라졌다 합쳐진 그대로 (병합 커밋) | 한 줄 |
| 기존 커밋 | 그대로 유지 | 새 커밋으로 다시 만듦 (해시 변경) |
| 충돌 해결 | 한 번 | 다시 적용하는 커밋마다 |
| 공유된 브랜치 | 안전 | 위험 |
| 되돌리기 | 병합 커밋 하나를 되돌리면 됨 | `reflog`로 원래 커밋을 찾아야 함 |
| 남는 정보 | 언제 어떤 브랜치가 합쳐졌는지 | 각 커밋이 어떤 변경인지만 깔끔하게 |

> **둘 다 커밋을 지우지 않는다.** 리베이스도 원래 커밋을 삭제하는 게 아니라 브랜치가 새 커밋을 가리키게 할 뿐이고, 원래 커밋은 `reflog`가 만료되고 `git gc`가 돌기 전까지 남아 있다.

### 리베이스를 쓰면 안 되는 경우
+ **다른 사람이 이미 가져간 커밋은 리베이스하지 않는다**
    - 원격에 푸시했다는 것 자체보다, 다른 사람이 그 커밋을 받아 그 위에 작업했을 수 있다는 것이 문제다
+ 문제가 생기는 과정
    1. 내가 D, E를 푸시하고 동료가 받아서 그 위에 F를 쌓는다
    2. 내가 D, E를 리베이스해 D', E'를 만들고 강제 푸시한다
    3. 동료가 pull하면 원래 D, E와 새 D', E'가 **같은 변경인데 다른 커밋**으로 히스토리에 함께 들어간다
+ 혼자 쓰는 브랜치(예: PR 브랜치)라면 푸시한 뒤에도 리베이스할 수 있다
    - 해시가 바뀌었으므로 일반 `push`는 거부되고 강제 푸시가 필요하다
    - `--force` 대신 **`--force-with-lease`** 를 쓴다. 내가 마지막으로 확인한 이후 원격에 다른 사람의 커밋이 올라왔으면 푸시를 거부해 덮어쓰지 않는다

```bash
git push --force-with-lease origin feature
```

### 자주 쓰는 방식
+ `git pull --rebase`
    - `pull`은 기본적으로 `fetch` + `merge`라서, 원격과 갈라질 때마다 의미 없는 병합 커밋이 생긴다
    - `--rebase`를 붙이면 `fetch` + `rebase`로 내 로컬 커밋을 원격 커밋 위에 다시 쌓는다
    - 아직 푸시하지 않은 내 커밋만 다시 만들어지므로 안전하다
+ 작업 브랜치는 리베이스로 최신 `main`을 따라가고, `main`에 합칠 때는 머지
    - 작업 중 히스토리는 깔끔하게, 합친 기록은 병합 커밋으로 남긴다

```bash
git config --global pull.rebase true   # pull할 때 항상 리베이스
git log --oneline --graph --all        # 머지와 리베이스 결과 모양 비교
```
