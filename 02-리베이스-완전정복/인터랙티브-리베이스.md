## 인터랙티브 리베이스

일반 리베이스는 커밋을 그대로 다시 쌓지만, 인터랙티브 리베이스(`-i`)는 다시 쌓기 전에 **어떤 커밋을 어떻게 다시 만들지 직접 지시**할 수 있다  
푸시하기 전에 지저분한 작업 커밋을 정리하는 데 주로 쓴다

+ 할 수 있는 일
    - 커밋 메시지 변경
    - 커밋 순서 변경
    - 여러 커밋을 하나로 합치기 (squash, fixup)
    - 커밋 수정, 커밋 하나를 여러 개로 나누기 (edit)
    - 커밋 삭제 (drop)

### 시작하기
```bash
git rebase -i HEAD~3    # 최근 커밋 3개를 다시 쌓는다
git rebase -i main      # main 이후 내 브랜치의 커밋 전부
git rebase -i --root    # 첫 커밋부터 전부
```

+ 지정한 커밋은 **기준점**이라 목록에 들어가지 않는다. `HEAD~3`이면 그 위의 커밋 3개(`HEAD~2`, `HEAD~1`, `HEAD`)가 대상
+ 실행하면 편집기에 **todo 목록**이 열린다. 저장하고 닫으면 위에서부터 차례로 실행된다

```
pick 127d5e9 로그인 화면 추가
pick 9c7e945 로그인 검증 로직
pick 6ab95d5 오타 수정

# Rebase <기준 커밋>..<끝 커밋> onto <기준 커밋> (3 commands)
#
# Commands:
# p, pick <commit> = use commit
# r, reword <commit> = use commit, but edit the commit message
# e, edit <commit> = use commit, but stop for amending
# s, squash <commit> = use commit, but meld into previous commit
# f, fixup [-C | -c] <commit> = like "squash" but keep only the previous
#                    commit's log message, ...
# x, exec <command> = run command (the rest of the line) using shell
# b, break = stop here (continue rebase later with 'git rebase --continue')
# d, drop <commit> = remove commit
# ...
# These lines can be re-ordered; they are executed from top to bottom.
#
# If you remove a line here THAT COMMIT WILL BE LOST.
```

> todo 목록은 **오래된 커밋이 위**에 있다. 최신 커밋이 위에 나오는 `git log`와 순서가 반대다.

### 명령어

| 명령 | 줄임 | 하는 일 |
|------|:---:|--------|
| `pick` | `p` | 커밋을 그대로 사용 |
| `reword` | `r` | 커밋은 그대로, 메시지만 수정 |
| `edit` | `e` | 커밋을 적용한 뒤 멈춤. 내용을 고치거나 나눈 뒤 `--continue` |
| `squash` | `s` | 바로 위 커밋과 합침. 두 메시지를 합쳐 편집 |
| `fixup` | `f` | 바로 위 커밋과 합침. 이 커밋의 메시지는 버림 |
| `drop` | `d` | 커밋 삭제. 줄을 지워도 같다 |
| `exec` | `x` | 그 위치에서 셸 명령 실행. 실패하면 멈춤 |
| `break` | `b` | 그 위치에서 멈춤. `--continue`로 이어감 |

### 메시지 변경: `reword`
```
pick   127d5e9 로그인 화면 추가
reword 9c7e945 로그인 검증 로직      ← 저장하면 이 커밋의 메시지 편집기가 열린다
pick   6ab95d5 오타 수정
```

+ 마지막 커밋 하나의 메시지만 고친다면 `git commit --amend`가 더 간단하다

### 순서 변경
+ todo 목록에서 줄의 순서를 바꾸면 그 순서대로 다시 쌓는다
+ 뒤의 커밋이 앞 커밋의 변경에 기대고 있으면(같은 줄을 고쳤다면) 순서를 바꿀 때 **충돌**이 난다

### 합치기: `squash`와 `fixup`
```
pick   127d5e9 로그인 화면 추가
squash 6ab95d5 오타 수정            ← 위 커밋과 합쳐 커밋 하나가 된다
pick   9c7e945 로그인 검증 로직
```

+ 합칠 커밋은 **합쳐질 커밋 바로 아래**에 두어야 한다. 필요하면 순서를 먼저 옮긴다
+ `squash`는 두 메시지를 모두 보여주고 편집하게 하고, `fixup`은 위 커밋의 메시지만 남긴다
+ 첫 줄은 `squash`·`fixup`으로 시작할 수 없다. 합칠 대상(위 커밋)이 없기 때문

### `fixup!` 커밋과 `--autosquash`
+ 이전 커밋을 고칠 변경이 생겼을 때 `--fixup`으로 커밋하면 메시지가 `fixup! <원래 메시지>`인 커밋이 생긴다
+ 나중에 `--autosquash`로 리베이스하면 todo 목록에서 **알아서 대상 커밋 아래로 옮기고 `fixup`으로 바꿔 준다**

```bash
git commit --fixup=127d5e9            # "fixup! 로그인 화면 추가" 커밋 생성
git rebase -i --autosquash main
```

```
pick 127d5e9 로그인 화면 추가
fixup 1e6bdb5 fixup! 로그인 화면 추가    ← 자동으로 위치와 명령이 정해짐
pick 9c7e945 로그인 검증 로직
pick 6ab95d5 오타 수정
```

+ `git config --global rebase.autoSquash true`로 두면 `-i`만 써도 항상 적용된다

### 수정하기와 나누기: `edit`
+ `edit`로 표시한 커밋을 적용한 직후 멈춘다
+ 내용 수정: 파일을 고치고 `git commit --amend` 후 `git rebase --continue`
+ 커밋 하나를 둘로 나누기

```bash
# todo에서 나눌 커밋을 edit로 바꾸고 저장 → 그 커밋에서 멈춤
git reset HEAD~               # 커밋만 취소하고 변경은 작업 디렉터리에 남긴다
git add 화면.js && git commit -m "로그인 화면 추가"
git add 검증.js && git commit -m "로그인 검증 로직"
git rebase --continue
```

### 삭제: `drop`
+ `drop`으로 바꾸거나 그 줄을 지우면 커밋이 사라진다
+ 뒤의 커밋이 삭제한 커밋의 변경에 기대고 있으면 충돌이 난다

### 커밋마다 테스트하기: `exec`
```bash
git rebase -i --exec "npm test" main
```

+ 각 `pick` 줄 아래에 `exec npm test`가 들어가, 커밋을 다시 쌓을 때마다 테스트를 돌린다
+ 실패하면 그 커밋에서 멈추므로 **어느 커밋이 깨뜨렸는지** 바로 알 수 있다

### 주의할 점
+ 인터랙티브 리베이스도 리베이스라서 대상 커밋의 **해시가 모두 바뀐다**. 다른 사람과 공유한 커밋에는 쓰지 않는다
+ 중간에 꼬이면 `git rebase --abort`로 시작 전 상태로 돌아간다. 이미 끝났다면 `reflog`로 되돌린다
+ 기본 편집기가 vim이라 불편하면 바꿔 둔다: `git config --global core.editor "code --wait"`
